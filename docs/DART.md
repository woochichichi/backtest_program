# DART 재무 데이터

marcap 에는 시세만 있고 재무제표가 없다. 전략3의 종목 스크리닝 3개 —
**부채비율 200% 미만 / 유동비율 100% 초과 / 영업이익 최근 4개 분기 연속 흑자** —
는 재무 데이터가 있어야 판정할 수 있다. 그걸 금융감독원 전자공시(DART) 오픈API 로 채운다.

---

## 1. 받는 방법 (3단계)

| 순서 | 파일 | 하는 일 | 걸리는 시간 |
|---|---|---|---|
| 1 | `test_dart.bat` | 인증키·연결 확인 + 삼성전자 1건 실제 조회 | 5초 |
| 2 | `update_dart.bat` | 2015년부터 올해까지 전 종목 재무 수집 | 처음 20~40분 / 이후 1~3분 |
| 3 | `dart_report.bat` | 받은 데이터가 제대로인지 진단 (인터넷 안 씀) | 10~60초 |

**반드시 `test_dart.bat` 을 먼저 실행하라.** 키가 틀렸거나 네트워크가 막혀 있으면
`update_dart.bat` 은 40분을 헛돌지 않고 바로 알려준다.

### 인증키

1. <https://opendart.fss.or.kr> 회원가입 → **오픈API 인증키 신청**. 보통 즉시 발급된다.
2. 발급받은 40자리 키를 프로젝트 폴더의 **`dart_key.txt`** 에 한 줄로 저장한다.
3. 또는 환경변수 `DART_API_KEY` 에 넣는다. **환경변수가 파일보다 우선**이다.

```
backtest_program/
└─ dart_key.txt      ← 여기. .gitignore 에 들어 있어 커밋되지 않는다
```

> 키를 코드나 문서에 하드코딩하지 마라. `tools/fetch_dart.py` 는 파일/환경변수에서만 읽고,
> 화면에 찍을 때도 `abcd****wxyz (40자)` 로 가린다.

### 명령줄로 직접 쓰기

```bash
python -m tools.fetch_dart --selftest              # test_dart.bat 이 부르는 것
python -m tools.fetch_dart --from 2015             # update_dart.bat 이 부르는 것
python -m tools.fetch_dart --report                # dart_report.bat 이 부르는 것
python -m tools.fetch_dart --rebuild               # 안 받고 파생 지표만 다시 계산
python -m tools.fetch_dart --only 2015-1,2015-2    # 이 분기만 콕 집어 다시
python -m tools.fetch_dart --from 2015 --force     # 받은 것 무시하고 전부 다시
python -m tools.fetch_dart --from 2020 --to 2022 --batch 100
```

| 옵션 | 기본값 | 설명 |
|---|---|---|
| `--from` / `--to` | 2015 / 올해 | 수집 연도 범위 |
| `--out` | `dart` | 저장 폴더 |
| `--batch` | 50 | 한 번에 조회할 회사 수 (최대 100) |
| `--force` | 꺼짐 | 이미 받은 분기까지 전부 다시 받는다 |
| `--refresh-recent` | 2 | 정정공시 대비로 매번 다시 확인할 최근 분기 수. `0` 이면 안 함 |
| `--refresh-corp-map` | 꺼짐 | 기업 고유번호 매핑만 새로 받는다 |
| `--disclosure-lag-days` | 45 | 분기 종료 후 이 일수가 지나야 요청한다 |
| `--annual-lag-days` | 90 | 사업보고서(4분기) 기준 일수 |
| `--only` | 없음 | 이 분기만 받는다. `2015-1,2015-2` 또는 `2015Q1`. **이미 받았든 제공 구간 밖이든 무조건 요청** |
| `--rebuild` | 꺼짐 | 받아 둔 `.parts` 로 연도 파일만 다시 만든다. **네트워크를 쓰지 않는다** |
| `--report` | 꺼짐 | 진단 리포트를 낸다. 인증키도 네트워크도 필요 없다 |
| `--quarterly-from` | 2016 | DART 가 분기·반기보고서를 주는 첫 연도. 그 이전 1~3분기는 요청하지 않는다 |
| `--sleep` | 0 | 호출 사이 대기 초. DART 가 버거워하면 `0.1` 정도 |
| `--resume` | - | 구버전 호환용. **기본 동작이라 아무 효과 없다** |

## 2. 같은 자료를 두 번 받지 않는다

분기 재무는 한 번 확정되면 거의 바뀌지 않는다. 그래서 **기본 동작이 "이미 받은 분기는 건너뛴다"** 다.
`update_dart.bat` 을 매일 눌러도 새로 나온 분기만 받는다.

판단 근거는 `dart/.fetch_state.json` 이다.

```json
{
  "version": 2,
  "quarters": {
    "2024-4": { "fetched_at": "2026-08-05 12:00:00", "rows": 2681, "corps": 2712, "complete": true }
  },
  "corp_map_fetched_at": "2026-08-05 11:58:00",
  "api_calls_today": 1084,
  "api_calls_date": "2026-08-05"
}
```

| 규칙 | 동작 |
|---|---|
| `complete: true` 인 분기 | 건너뛴다 |
| **가장 최근 2개 분기** | `complete` 여도 **매번 다시 받는다** (정정공시·지각제출) |
| 아직 공시 기간이 아닌 분기 | **아예 요청하지 않는다** (아래 3장) |
| `corp_map_fetched_at` 이 오늘 | 기업 고유번호를 다시 받지 않는다 |
| `--force` | 위 전부 무시하고 다시 받는다 |

실행하면 왜 건너뛰는지 화면에 다 나온다.

```
  2024-1  건너뜀 (이미 받음, 2,681행)
  2024-2  건너뜀 (이미 받음, 2,690행)
  2026-1  받는 중... [최근 분기 재확인]  (배치 50)
  2026-1  받는 중...  54%  (1,468/2,712 종목, 남은 예상 2분 10초)
  2026-2  건너뜀 (아직 공시 기간이 아님, 2026-08-14 이후 수집)
  2026-3  건너뜀 (아직 공시 기간이 아님, 2026-11-14 이후 수집)
```

## 3. 아직 공시되지 않은 분기는 요청하지 않는다

분기·반기보고서의 법정 제출 기한은 **분기 종료 후 45일**, 사업보고서는 **사업연도 종료 후 90일**이다.
그 전에 요청해 봐야 `013`(데이터 없음) 만 잔뜩 돌아오고 호출만 낭비된다.

| 분기 | 종료일 | 조회 시작일 |
|---|---|---|
| 1분기 (`11013`) | 3/31 | 5/15 |
| 반기 (`11012`) | 6/30 | 8/14 |
| 3분기 (`11014`) | 9/30 | 11/14 |
| 사업보고서 (`11011`) | 12/31 | 다음 해 3/31 |

### DART 가 아예 주지 않는 구간

**2015년 1분기·반기·3분기는 DART 재무정보 API 에 없다.** 2015년은 사업보고서(연간)만 있고,
분기·반기보고서는 **2016년부터** 제공된다. 이건 우리 수집기의 버그가 아니라 DART 쪽 제공 범위다.

사용자 실측(2026-08 수집):

```
연도      1분기     반기    3분기  사업보고서      합계
2015          X        X        X       1,841     1,841
2016      1,772    1,816    1,830       1,868     7,286
```

그래서 `plan_quarters` 는 `--quarterly-from`(기본 2016) 이전 연도의 1~3분기를
**아예 요청하지 않는다.** 요청해 봐야 `013` 만 돌아오고 연 186회씩 호출을 버린다.
`dart_report.bat` 도 이 구간의 공백은 오류가 아니라 "참고" 로만 표시한다.

직접 확인하고 싶으면 강제로 요청할 수 있다.

```bash
python -m tools.fetch_dart --only 2015-1,2015-2,2015-3
```

> 2026-08-05 에 실행하면 **2026 반기는 아직 대상이 아니다** (8/14부터).
> 빨리 받고 싶으면 `--disclosure-lag-days 30` 처럼 줄여라. 다만 일찍 낸 회사만 잡히고
> 나머지는 `013` 이 되며, 그 분기는 `complete` 로 기록되므로 나중에 채워 넣으려면
> `--refresh-recent` 범위 안에 들거나 `--force` 가 필요하다.

## 4. 저장되는 파일

```
dart/
├─ corp_map.parquet              # 기업 고유번호(8자리) <-> 종목코드(6자리)
├─ fundamentals-2015.parquet     # 연도별 재무
├─ fundamentals-2016.parquet
│  ...
├─ .fetch_state.json             # 진행 상태 (이어받기·호출 수)
└─ .parts/                       # 분기별 원본 조각. 연도 파일을 다시 만들 때 쓴다
```

`dart/` 폴더 전체가 `.gitignore` 되어 있다.

### `fundamentals-YYYY.parquet` 컬럼

| 컬럼 | 형 | 설명 |
|---|---|---|
| `code` | string | 6자리 종목코드. **marcap 의 `Code` 와 이걸로 잇는다** |
| `corp_code` | string | DART 기업 고유번호 8자리 |
| `year` | Int32 | 사업연도 |
| `quarter` | Int8 | 1=1분기 2=반기 3=3분기 4=사업보고서 |
| `disclosed_at` | datetime64 | **접수일자.** `rcept_no` 앞 8자리. as-of 판정의 기준 |
| `fs_div` | string | `CFS`=연결 / `OFS`=별도. **연결 우선, 없으면 별도** |
| `currency` | string | 통화. 보통 `KRW` |
| `유동자산` `유동부채` `자산총계` `부채총계` `자본총계` | Int64 | **원 단위** 재무상태표 항목 (시점 값) |
| `매출액` `영업이익` `당기순이익` | Int64 | **원 단위** 손익계산서 항목. **누적값** |
| `debt_ratio_pct` | float64 | 부채총계 / 자본총계 × 100 |
| `current_ratio_pct` | float64 | 유동자산 / 유동부채 × 100 |
| `op_income_quarter` | Int64 | **차분한 분기 영업이익** (아래 6장) |
| `capital_impaired` | boolean | 자본총계 <= 0 (자본잠식). 값이 없으면 `pd.NA`(모름) |

금액 컬럼은 pandas 의 nullable `Int64` 다. 값이 없으면 `NaN` 이 아니라 `pd.NA` 이며,
**0 이나 임의값으로 채우지 않는다.** 모르는 건 끝까지 모르는 채로 둔다.

### 비율을 계산하지 않는 경우 (분모 방어)

`debt_ratio_pct` / `current_ratio_pct` 는 다음 셋 중 하나면 **계산하지 않고 비워 둔다.**

| 상황 | 왜 |
|---|---|
| 분자·분모 원자료가 없음 | 계산할 수가 없다 |
| 분모 <= 0 | 자본잠식·유동부채 0. 음수나 무한대 비율은 의미가 없다 |
| **분모 < 자산총계의 0.01%** | 유동부채 1,000원인 껍데기 회사에서 유동비율 **52억%** 가 나온다 |

세 번째가 핵심이다. 실제 수집 데이터에서 유동비율 최대가 **5,258,199,024%** 로 찍혔다.
이런 값을 그대로 두면 "유동비율 100% 초과" 필터를 **무조건 통과**해 필터가 통째로 무력해진다.
그래서 기준(`MIN_DENOM_RATIO = 0.0001`) 미만이면 값을 만들지 않는다.

**자본잠식은 부채비율로 거르지 않는다.** 자본총계가 음수면 부채비율도 음수가 되어
"200% 미만" 을 그냥 통과해 버린다. 대신 `capital_impaired = True` 플래그로 따로 표시하니
전략에서 이 컬럼으로 직접 걸러라.

> `capital_impaired` 는 아직 `engine/dart.py` 의 `FUNDAMENTAL_COLUMNS` 에 없어
> `DartStore.as_of()` 로는 나오지 않는다. parquet 에는 저장되어 있다.
> 엔진 쪽에 이 컬럼을 추가해야 백테스트에서 쓸 수 있다.

이미 받아 둔 데이터에 새 규칙을 적용하려면 **다시 내려받을 필요 없이**:

```bash
python -m tools.fetch_dart --rebuild      # .parts 로 파생 지표만 다시 계산. 인터넷 안 씀
```

## 5. as-of 규칙 — 이 문서에서 가장 중요한 부분

### 왜 필요한가

재무제표는 **분기가 끝난 뒤 45~90일이 지나서 공시된다.** 2025년 1분기 재무는 빨라야 5월 중순에 나온다.

그런데 백테스트에서 2025-04-01 자 매매 판단에 2025Q1 재무를 쓰면,
**그날 세상에 존재하지도 않던 정보로 종목을 고른 것**이 된다. 이걸 룩어헤드 편향(look-ahead bias)이라 한다.
결과는 항상 실제보다 좋게 나온다. 실전에서는 절대 재현되지 않는다.

> 이 프로젝트에는 같은 성격의 문제로 전략 수익률이 **+122% → -14%** 로 뒤집힌 전례가 있다.
> 그때 무엇이 잘못됐는지 모르고 배포했다면 실제 돈을 잃었을 것이다.

### 어떻게 막는가

모든 조회는 `disclosed_at <= 조회일` 인 행만 본다. 이 필터를 통과한 것 중에서
가장 최신 (연도, 분기) 를 고른다.

```python
from engine.dart import DartStore

store = DartStore(root="dart")

store.as_of("005930", "2025-05-14")   # -> 2024Q4 (2025Q1 은 5/15 공시라 아직 안 보임)
store.as_of("005930", "2025-05-15")   # -> 2025Q1
store.as_of("005930", "2025-04-01")   # -> 2024Q4. 분기는 끝났지만 공시 전이다
```

**`DartStore.as_of()` / `as_of_panel()` / `consecutive_profit_quarters()` 를 거치지 않고
parquet 을 직접 읽어 필터링하면 이 보호가 통째로 무력화된다.** 하지 마라.

### API

```python
store.available          # -> bool. dart 폴더가 없으면 False. import 는 언제나 성공한다
store.status()           # -> {"available", "last_fetch", "year_range", "row_count", "codes"}

store.as_of(code, date)              # -> dict | None
store.as_of_panel(codes, date)       # -> pd.DataFrame (index=code). 백테스트 스캔용 벡터 조회
store.consecutive_profit_quarters(code, date)   # -> int | None
```

데이터가 아예 없으면 `engine.errors.DataUnavailable` 을 던진다.
데이터는 있는데 그 종목/그 시점에 공시가 없으면 `as_of` 는 `None`,
`as_of_panel` 은 **빈 DataFrame**(예외 아님) 을 돌려준다.

스캔 루프에서는 종목마다 `as_of` 를 부르지 말고 `as_of_panel` 을 한 번 불러라.

```python
fund = store.as_of_panel(candidate_codes, today)
ok = fund[(fund["debt_ratio_pct"] < 200) & (fund["current_ratio_pct"] > 100)]
```

`< 200` 비교는 값이 `pd.NA` 인 행을 자동으로 떨어뜨린다. 즉 **모르는 종목은 통과하지 못한다.**
의도한 동작이다.

## 6. 분기 손익은 누적값에서 차분한다

손익계산서(IS) 금액은 **누적**이다. 반기보고서의 영업이익은 1~6월 합계고,
사업보고서의 영업이익은 1~12월 합계다. 그대로 쓰면 "분기 흑자"를 판정할 수 없다.

```
Q1 = 1분기 누적
Q2 = 반기 누적        - 1분기 누적
Q3 = 3분기 누적       - 반기 누적
Q4 = 사업보고서(연간) - 3분기 누적
```

이 계산 결과가 `op_income_quarter` 다.

재무상태표(BS) 항목(`유동자산`, `부채총계`, `자본총계` …)은 **시점 값이므로 차분하지 않는다.**

### 결측은 "모른다"로 둔다

중간 분기가 빠져 있으면 그 분기와 그 다음 분기는 `None` 이다.

```python
quarterly_from_cumulative({1: 100, 2: None, 3: 420, 4: 600})
# -> {1: 100, 2: None, 3: None, 4: 180}
#            ↑ 반기를 모름   ↑ 반기를 모르니 3분기도 모름
```

연결(CFS)과 별도(OFS)가 분기별로 섞여 있으면 그 사이도 차분하지 않는다(`None`).
기준이 다른 숫자를 빼면 값이 엉킨다.

**어떤 경우에도 빠진 분기를 0 이나 흑자로 가정하지 않는다.**

### `consecutive_profit_quarters`

가장 최근 공시 분기부터 (연도, 분기) 를 1씩 거슬러 내려가며 `op_income_quarter > 0` 인 분기를 센다.

| 상황 | 반환 |
|---|---|
| 적자(`<= 0`) 를 만남 | 거기서 멈추고 지금까지 센 수 |
| 결측(값 없음 / 그 분기 행 자체가 없음) | 거기서 멈춘다. **흑자로 세지 않는다** |
| 가장 최근 분기의 값 자체를 모름 | `None` |
| 그 종목 공시가 하나도 없음 | `None` |

```python
n = store.consecutive_profit_quarters("005930", "2025-06-30")
ok = n is not None and n >= 4        # 이렇게 쓴다
```

결측으로 멈춘 경우와 적자로 멈춘 경우가 같은 숫자로 나오므로, 이 값은
**"최소 이만큼은 확실하다"** 로 읽어야 한다. `n >= 4` 판정은 항상 실제보다 적게(보수적으로)
나오며, **없는 흑자를 만들어내는 방향으로는 틀리지 않는다.**

## 7. 호출 한도와 이어받기

DART 는 인증키 하나로 **하루 20,000건**까지만 부를 수 있다.

`fetch_dart` 는 자기가 몇 번 불렀는지 `.fetch_state.json` 의 `api_calls_today` 에 세어 둔다.
날짜가 바뀌면 자동으로 0 이 된다. 한도에 도달하면 **DART 가 `020` 을 주기 전에 스스로 멈추고**
지금까지 받은 것을 저장한다. 남은 호출이 500건 밑으로 내려가면 경고를 찍는다.

### 예상 호출 수

배치 50, 상장사 약 2,700개 기준으로 **한 분기당 54회**.

| 범위 | 분기 수 | 호출 수 | 하루 한도 대비 |
|---|---|---|---|
| 2015~2026 전체 (첫 수집) | 45 | 약 2,431 | **약 12%** |
| 매일 갱신 (최근 2분기 재확인) | 2 | 약 108 | 약 0.5% |
| 배치 100 으로 첫 수집 | 45 | 약 1,216 | 약 6% |

즉 **첫 수집도 하루 한도의 1/8 이면 끝난다.** 한도 때문에 며칠에 나눠 받을 일은 거의 없다.

### 중간에 끊기면

전원이 나가든 창을 닫든 네트워크가 끊기든, **다시 `update_dart.bat` 을 실행하면 이어받는다.**
분기 단위로 저장하므로 이미 끝난 분기를 다시 받지 않는다.

## 10. 진단 리포트 — `dart_report.bat`

받은 데이터가 제대로인지 확인하는 도구. **인터넷을 쓰지 않는다.**
결과를 화면에 보여주면서 `logs\dart_report.txt` 로도 저장한다(CP949, 메모장에서 바로 열린다).

```bash
python -m tools.fetch_dart --report            # dart_report.bat 이 부르는 것
```

| 절 | 보는 것 |
|---|---|
| (가) 수집 현황 | 파일 수·행 수·연도 범위·마지막 수집 시각, 분기별 행 수 표, marcap 대비 커버리지 |
| (나) 파싱 점검 | 항목별 결측률, 파생 지표 분포, **분모 방어 건수**, 자본잠식 수, 음수 파싱, `fs_div` 분포 |
| (다) 대표 종목 샘플 | 삼성전자·SK하이닉스·적자 이력 종목의 분기별 숫자 |
| (라) as-of 동작 | 조회일 vs 공시일. **하나라도 어긋나면 크게 경고** |
| (마) 생존 편향 | 재무가 없는 종목 규모와 `on_missing` 선택지 |

마지막에 `정상` 또는 `확인 필요 - N건` 판정이 나온다. 종료 코드는 0 / 1 / 2(데이터 없음).

### 무엇을 잡아내는가

| 증상 | 리포트가 하는 말 | 진짜 원인 |

| 특정 항목만 결측률 30% 초과 | `'영업이익' 항목이 90% 결측입니다` | `account_nm` 매칭 실패 |

## 11. 문제 해결

| 증상 | 원인과 해결 |
|---|---|
| `인증키를 찾을 수 없습니다` | `dart_key.txt` 가 없거나 비었다. 프로젝트 폴더 바로 아래에 두었는지 확인 |
| `인증키 오류 (status=010)` | 키에 따옴표·공백·줄바꿈이 섞였을 수 있다. 40자리만 한 줄로 |

| `시스템 점검 중` | DART 쪽 사정. 몇 십 분 뒤 재시도 |
| 받았는데 종목이 적다 | 상장폐지·신규상장으로 그 시점에 없던 회사다. `corp_map.parquet` 은 **현재 상장사만** 담는다 (11장) |
| 특정 회사가 통째로 없다 | 그 회사가 주요계정 API 대상이 아니거나 보고서를 안 냈다. `013` 은 정상 응답이다 |
| 다시 받고 싶다 | `python -m tools.fetch_dart --from 2015 --force` |
| 2015년 1~3분기가 비었다 | **정상이다.** DART 가 그 구간 분기보고서를 주지 않는다 (3장) |

| 계산 규칙이 바뀌었다는데 다시 받기 싫다 | `python -m tools.fetch_dart --rebuild` (인터넷 안 씀) |
| 유동비율이 몇 억 %로 나온다 | 옛날 규칙으로 받은 파일. `--rebuild` 하면 분모 방어가 적용된다 |

## 12. 알려진 한계 - 반드시 알고 써라

1. **`corp_map` 은 "지금" 상장된 회사만 담는다.**
   `corpCode.xml` 에서 `stock_code` 가 빈 값이면 버리는데, 과거에 상장했다가 지금은
   상장폐지된 회사도 `stock_code` 가 비어 있다. 따라서 **상장폐지 종목의 과거 재무는 수집되지 않는다.**
   실측 규모: marcap 에 등장하는 3,560종목 중 **502종목(14.2%)** 에 재무가 없다
   (현재 상장인데 미커버 262 + 상장폐지 추정 240).

   이 종목들을 어떻게 다룰지는 `universe.filters.on_missing` 이 정한다.

   | 설정 | 동작 | 대가 |
   |---|---|---|
   | `"include"` (기본값) | 재무를 모르면 그냥 통과 | 그 502종목에는 재무 조건이 **적용되지 않는다.** 필터가 의도만큼 걸러내지 못한다 |
   | `"exclude"` | 재무를 모르면 후보에서 제외 | 재무 조건은 온전히 적용되지만, 상장폐지 종목이 통째로 빠져 **생존 편향**이 생긴다 |

   어느 쪽도 공짜가 아니다. **두 설정으로 각각 돌려 결과 차이를 보는 편이 가장 안전하다.**
   차이가 크면 그 전략은 재무 필터가 아니라 생존 편향에 기대고 있다는 뜻이다.

2. **정정공시를 만나면 원래 숫자가 사라진다.**
   같은 분기를 다시 받으면 그 분기 조각 파일을 덮어쓴다. 정정된 값의 `disclosed_at` 은
   정정 접수일이므로 as-of 필터는 여전히 올바르게 동작하지만, **정정 전에 시장이 보고 있던
   원래 숫자는 남지 않는다.** (스토어 자체는 같은 분기의 여러 벌을 넣어 두면
   시점별로 올바르게 골라 준다. 수집 쪽이 한 벌만 남길 뿐이다.)

3. **`op_income_quarter` 의 Q4 는 사업보고서에 의존한다.**
   3분기 보고서를 안 낸 회사는 Q4 분기값을 알 수 없어 `None` 이 된다.

4. **`fs_div` 가 분기마다 바뀌면 그 사이는 차분하지 않는다.**
   연결로 내다가 별도로 바꾼 회사는 그 경계 분기가 `None` 이 된다.

5. **주요계정 API 는 계정 이름이 회사마다 조금씩 다르다.**
   `영업이익(손실)`, `수익(매출액)` 같은 변형은 정규화하지만, 전혀 다른 이름을 쓰는
   회사(특히 금융업)는 해당 계정이 비어 있을 수 있다. 금융업은 `유동자산`/`유동부채` 구분
   자체가 없어 유동비율이 비는 경우가 많다.
